      4. JAX-COSMO cubic approximation of the SFH

      Nodes are extracted from the native Diffstar SFH. jax_cosmo.scipy.interpolate.InterpolatedUnivariateSpline runs with k=3 and the not-a-knot endpoint condition in log-time and log-SFR. The curve is then normalized to the same surviving stellar mass before DSPS.

      Comparison within the current runtime. Both photometry calculations use exactly the same SSPs, MDF, dust, IGM, filters, and versions. Their residual therefore isolates the spline approximation and must not be confused with historical-parquet runtime drift.

      1. From normalized node positions to cosmic time

      The production latent stores one shared length-11 node grid, not eleven free times per galaxy.

      u_i in [0, 1],  i = 0,...,10
ell_min = log10(0.05 Gyr)
ell_obs = log10(t_obs)
ell_i = ell_min + u_i (ell_obs - ell_min)
t_i = 10^ell_i

u_0 = 0,  u_10 = 1

      The normalized positions u_i are shared by every galaxy. Redshift changes t_obs, so the same normalized grid is stretched to the cosmic-time interval available to that object. The endpoints are always 0.05 Gyr and the observation time.

      The interactive example below uses the node count and grid selected by the report builder. The production 15D latent uses the fixed optimized 11-node vector shown in the 15D latent tab.

      2. From ten contrasts to eleven log-SFR values

      The latent keeps SFH shape and deliberately discards its common amplitude.

      q_i = y_(i+1) - y_i,  i = 0,...,9
y_0^rel = 0
y_i^rel = sum_(j=0)^(i-1) q_j

y_i = y_i^rel + c_mass
SFR_i = 10^y_i

      The ten adjacent differences q_i reconstruct eleven relative node heights by a cumulative sum. Adding the same constant to every node changes only the overall SFR amplitude, not the shape. That constant is recovered later from log10_stellar_mass, which is why eleven node values require only ten independent SFH coordinates.

      3. JAX-COSMO cubic not-a-knot interpolation

      A different cubic polynomial is used on each interval, with a globally smooth curve.

      For ell in [ell_i, ell_(i+1)]:
S_i(ell) = a_i + b_i Delta + c_i Delta^2 + d_i Delta^3
Delta = ell - ell_i

S_i(ell_i) = y_i
S_i(ell_(i+1)) = y_(i+1)
S_i'(ell_(i+1)) = S_(i+1)'(ell_(i+1))
S_i''(ell_(i+1)) = S_(i+1)''(ell_(i+1))

      InterpolatedUnivariateSpline(..., k=3) solves for the interval coefficients. Values, first derivatives, and second derivatives are continuous at interior knots. The not-a-knot endpoint condition makes the first two intervals share one cubic polynomial, and likewise for the last two intervals. No endpoint slope is stored or learned separately.

      Interpolation happens in log10(time) and log10(SFR). The physical curve is therefore positive after exponentiation: SFR(t)=10^S(log10(t)).

      4. Recovering the physical amplitude

      The spline shape is normalized through the same DSPS stellar-mass-loss calculation as the native SFH.

      SFR_rel(t) = 10^S(log10(t))
M_surv,rel = DSPS_surviving_mass[SFR_rel(t), SSP mass loss]
A = 10^log10_stellar_mass / M_surv,rel
SFR_final(t) = A * SFR_rel(t)
c_mass = log10(A)

age_weights = DSPS_age_weights[SFR_final(t)]
photometry = filters(IGM(dust(SSP x age_weights x M_formed)))

            7. Normalizing the 15D latent for the flow

            Each coordinate receives an invertible train-only marginal transform before it enters the RealNVP. The transform improves numerical conditioning; it does not remove multivariate dependence.

            Historical checkpoint contract. The values displayed here are serialized with the epoch-645 PCHIP-trained prior. The JAX-COSMO retraining must fit a new transform from its new training projection only. The formulas and support choices remain the intended production method.

            Before and after the marginal transforms

            The same training rows in physical and normalized coordinates.

            Shifted-asinh family: 13 coordinates

            Used for stellar mass, metallicity, dust slope, and all ten SFH contrasts.

            m = median_train(x)
q_lo = quantile_train(x, 0.1586552539)
q_hi = quantile_train(x, 0.8413447461)
lambda_robust = (q_hi - q_lo) / 2
lambda = max(lambda_robust,
             10^-6 std_train(x),
             10^-6)

r = asinh((x - m) / lambda)
center = mean_train(r)
scale = max(std_train(r), 10^-12)
y = (r - center) / scale

            m is stored as location. Around the median, asinh is approximately linear, so small differences remain resolved. In the tails it grows logarithmically, compressing large positive and negative excursions without clipping them.

            The central quantiles correspond to approximately minus/plus one Gaussian standard deviation. They provide a robust scale even when the raw marginal is skewed or heavy-tailed.

            Inverse: x = location + lambda * sinh(center + scale * y)

            Positive-support log family: 2 coordinates

            Used only for z_obs and dust_av, whose physical semantics require strict positivity.

            Require x > 0 for every training row
r = log(x)
center = mean_train(r)
scale = max(std_train(r), 10^-12)
y = (r - center) / scale

Inverse: x = exp(center + scale * y)

            The log transform makes invalid negative samples impossible after inversion. This support constraint is physical and does not depend on the empirical population distribution. A nonpositive training value is treated as a contract error rather than clipped.

            What normalization does

            Numerical conditioning

            • CentersEach transformed marginal near zero
            • ScalesEach transformed marginal to order-one variance
            • Compresses tailsSmoothly and invertibly, without hard bounds
            • Enforces supportPositive redshift and dust attenuation after inversion
            • SerializationAll parameters travel with the checkpoint

            What normalization does not do

            Remaining learning problem

            • Joint dependenceStill learned by the RealNVP
            • GaussianizationNot forced; marginals may remain non-Gaussian
            • WhiteningDisabled in the selected V6 checkpoint
            • Dirac atomsExact zero contrasts remain discrete atoms

            Roundtrip and checkpoint rule

            The decoder must use exactly the transform stored by the prior checkpoint.

            physical x --forward transform--> normalized y --inverse transform--> physical x

Required checks:
1. identical coordinate names and order;
2. identical family for every coordinate;
3. finite center, scale, location, and lambda values;
4. scale > 0 and lambda > 0;
5. forward/inverse roundtrip within the serialized tolerance;
6. encoder, prior, and DSPS decoder resolve the same checkpoint-backed transform.

            Normalization contract

            The parameters below are fitted on the training split and serialized with the checkpoint.

            Shifted-asinh family:
y = [asinh((x - location) / lambda) - center] / scale
x = location + lambda * sinh(center + scale * y)

Positive-support log family:
y = [log(x) - center] / scale,  x > 0
x = exp(center + scale * y)

            The shift follows the train median and lambda is a robust central scale. Asinh is nearly linear near the center and logarithmic in both tails, so broad skewed coordinates become trainable without hard clipping. Exact zero SFH contrasts remain exact atoms: a continuous flow can approximate their surrounding density but cannot assign non-zero probability mass to a mathematical Dirac delta.
